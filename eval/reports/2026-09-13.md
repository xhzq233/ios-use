## Computer Use 只读探查（单独统计）

在日常 Codex Home 启动一个仅进程级 `--enable computer_use` 的 Exec，
实际模型为 `gpt-6-astra / low`。任务耗时 161.054 s，进程 166.140 s，
总 tokens 493,270；不计入 iOS trial 或均值。

原生 Bundle 已定位：`Codex Computer Use.app`，Bundle ID
`com.openai.sky.CUAService`，版本 `26.902.1000968`，可执行文件
`Contents/MacOS/SkyComputerUseService`。本机安装在 Codex Home 的
`computer-use/` 下，宿主 `cua_node/lib/node_modules/@oai/sky/` 也带同版 Bundle。

本次插件版本 `26.903.61454` 的启动配置仍固定
`CUA_REPL_ENABLED_SURFACES=browser`，对应 `setupCUA({browser:true, computer:false})`。
所以 feature flag 并未使该 Exec 获得原生 App 方法：`getState()` 可用，
`listApps()` 实际报不存在。没有修改全局配置或调用可能启动 App 的 `getApp()`。

控制器直接回读了本地 Bundle 元数据和 JS 适配实现：`@oai/cua` 的
`create_tinysky_alt.js` 仅在原生后端存在时添加 `getApp/listApps`；App 方法经
`@oai/sky` 传递目标 app 与动作参数，Tab 方法则转至浏览器 AX 后端。
这是可查验的 JS 适配层与 Bundle 信息，不是对编译后原生内部实现或连接能力的验证。

原生入口是 `cua.getApp(nameOrBundleID)`，返回的 App 与 Tab 共享观察、点击、滚动、
输入等 Target 方法；App 不提供 Tab 的 goto/back/reload。
`getAXState({disableDiffing})` → `sky.get_app_state({app,disableDiff})` →
`MacComputerUseClient.getAppState()` → `ComputerUseIPCAppGetSkyshotRequest`。
客户端复用 `CodexComputerUseIPC-5` native-pipe 连接，按请求返回服务端 skyshot；
该 JS 路径没有暴露 quiescence 参数，也不能据此判断原生服务内部如何等动画。
不能从此推出 iOS Wait 有问题或需要模仿固定双读。

`task_complete.duration_ms`，总 tokens = input + output，缓存输入已含在 input。

提速结论，更不能把跨版本差异全归因于 MCP。
