## 轨迹复核

两轮均使用原始 CLI 的语义 `swipe --to 亮度 --from 构图`，一次命令内部滚动两次到达目标；
调节滑杆后另查看 UIKit `ui-tree`，再点击真正 Undo。没有通过把滑杆拖回中点冒充撤销，
也没有使用 Frida 脚本或其它 UI 通道。两轮主证据各四张均已独立查看。
R1 默认截图附带 OCR，R2 主证据使用 `--no-ocr`，这些自主选择保留在端到端计量中。
首页截图右缘存在页面退出过渡痕迹，R1 还显示 App 既存资源错误通知；首页主内容与返回动作
有直接证据，不声称验证了整个首页资源均正常。控制器最后另留首页截图，不回改候选原图。

## 阶段对照：优势不在同一个环节

以下是原始记录时间戳的近似分段，单位秒，均含模型决策 / 宿主调度 / 工具等待，
不是组件纯耗时。边界依次为任务开始、发起“导入照片”、发起“调节”入口点击、
发起改变亮度、发起 Undo、任务完成。日志落盘有毫秒级偏差；总耗时仍以上方
task_complete 的计量为准，不扣掉失败重试制造假想的“修好后成绩”。

| 阶段 | A1 | A2 | C1 | C2 | 204 均值 | CUA 均值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 起步：读资料、连接到首次导图 | 28.9 | 27.4 | 43.7 | 46.4 | 28.2 | 45.1 |
| 导图到进入调节 | 35.4 | 39.8 | 19.9 | 20.8 | 37.6 | 20.4 |
| 进入调节到改变亮度 | 29.1 | 27.3 | 47.4 | 33.5 | 28.2 | 40.5 |
| 改变亮度到发起 Undo | 20.7 | 21.7 | 8.2 | 4.9 | 21.2 | 6.6 |
| Undo 到取证 / 回首页 / 结束 | 25.3 | 22.2 | 42.8 | 20.1 | 23.8 | 31.4 |

- CUA 两轮导图阶段较短：读图后直接选择素材；CLI 两轮都另查 tap 帮助、单独读取截图，
  导图后还额外读取 DOM。这是实际路径差异，不等于证明接口知识迁移。
- 寻找亮度时，CLI 一条语义 swipe 内部完成两次滚动；CUA 先尝试 scroll，再两次拖动。
  C1 还经历截图 / 窗口定位错误恢复。原始 CLI 的语义操作能力有可见价值。
- 调亮到 Undo：CUA 两轮都看图直接点击撤销；CLI 两轮先查询 ui-tree，A1 还检索业务文档。
  这是可进一步验证的局部优势：减少对已可见控件的额外结构查询。
- C2 比 C1 少 9 次 CUA 回合，没有窗口错误恢复，且更多采用动作、AX、截图同次返回。
  C1 的窗口问题并非两轮共同缺陷，全部差异也不能只算成它的固定开销。
  CLI 本来就能批处理，不能将 C2 的回合减少称为 CUA 独有的新能力。

工程判断：本次支持继续定位和验证具体操作 / 观察路径，不支持仅因接口形似就扩大 MCP
改造。保留 CLI 的语义能力，考虑如何让已可见控件的操作和必要观察更直接；这些是从轨迹
得到的候选方向，不是已证明的优化方案。本次不新增修改或测试，210 仍跳过。

## 历史：独立 CLI 接入预检（不计样本）

控制器通过当前桌面官方 `cua_repl` 的原生 App API 实际完成同一亮度闭环，
含固定素材、+71、Undo 和回首页。它不是 fresh gpt-6-astra / low 评测，不统计其时间或 tokens。

独立 CLI 会话接入尝试使用应用自带的官方 `SkyComputerUseClient mcp`，它公开十个
原生工具，而不是当前桌面 `cua_repl` 的 JS 封装。两条通道不能混称完全相同的接口。

1. 原始 Codex 初始化携带 `capabilities.experimental.codex/auth-change` 时，官方接口解析失败。
   重放去除该字段的同一初始化可成功。私有诊断连接入口仅剔除此握手字段，其余字节原样传递；
   没有修改官方程序、工具声明、UI 操作逻辑或权限。
2. 兼容入口下，真实 Codex MCP 客户端连接成功并列出全部十个工具，但 `list_apps` 返回
   AppleEvent `-1712` 超时。重置控制器 CUA 会话后的独立检查仍在 20 秒工具限制处超时。
3. 候选均结束后，直接向准确的醒图 App 路径调用 `get_app_state` 也在 20 秒处超时，
   因而不是只缺 App 枚举；不能据工具已列出就宣称可正式运行。

这些是无模型的接入诊断，不是 Computer Use 的两个失败任务，不计入模型成功率。
尚未证明超时来自哪个权限、服务或宿主环节；未重启共享控制服务或绕过安全限制。
本次不继续改造该通道，不将控制器预检或其它 UI 工具冒充正式 C 样本。
