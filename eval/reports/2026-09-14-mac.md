## Computer Use：能完成手工预检，不等于独立评测可用

控制器通过当前桌面官方 `cua_repl` 的原生 App API 实际完成同一亮度闭环，
含固定素材、+71、Undo 和回首页。它不是 fresh gpt-6-astra / low 评测，不统计其时间或 tokens。

独立 CLI 会话接入尝试使用应用自带的官方 `SkyComputerUseClient mcp`，它公开十个
原生工具，而不是当前桌面 `cua_repl` 的 JS 封装。两条通道不能混称完全相同的接口。

1. 原始 Codex 初始化携带 `capabilities.experimental.codex/auth-change` 时，官方接口解析失败。
   重放去除该字段的同一初始化可成功。私有诊断连接入口仅剔除此握手字段，其余字节原样传递；
   没有修改官方程序、工具声明、UI 操作逻辑或权限。
2. 兼容入口下，真实 Codex MCP 客户端连接成功并列出全部十个工具，但 `list_apps` 返回
   AppleEvent `-1712` 超时。重置控制器 CUA 会话后的独立检查仍在 20 秒工具限制处超时。
3. 候选均结束后，直接向准确的醒图 App 路径调用 `get_app_state` 也在 20 秒处超时，
   因而不是只缺 App 枚举；不能据工具已列出就宣称可正式运行。

这些是无模型的接入诊断，不是 Computer Use 的两个失败任务，不计入模型成功率。
尚未证明超时来自哪个权限、服务或宿主环节；未重启共享控制服务或绕过安全限制。
本次不继续改造该通道，不将控制器预检或其它 UI 工具冒充正式 C 样本。
